# 长期格式版本与迁移设计

本文是未来任务的设计方案，不在当前开发阶段实施。当前项目仍保持版本 1、不做向后兼容、不做旧数据兼容；当存储格式需要进入生产级演进时，再按本文启用版本与迁移机制。

设计目标是让 collection 在跨版本升级、崩溃回滚和快照恢复时，能够明确判断“能读、能写、需要迁移、必须拒绝”，并且永远不依赖猜测来混合两代文件。

## 适用范围

- generation manifest：`generation.bin`。
- collection 元数据：`meta.bin`、`payload_indexes.json`、类型标记。
- dense 服务文件：向量、id tracker、删除位图、分段清单。
- payload 存储：tracker、journal、bitmask、页面、blob 文件。
- WAL：段头、记录编码、ACK 文件。
- 索引派生文件：HNSW、IVF、量化、字段索引。
- 快照清单与 segment manifest。

每类文件独立持有格式版本；collection 另有一个聚合格式版本，用来描述这些文件版本组合所代表的存储契约。

## 版本模型

### 文件级版本

每个持久化文件在头部保存 magic、格式版本和校验值。读取器按以下顺序判断：

1. magic 不匹配：视为不属于该存储，按损坏处理或隔离。
2. 版本高于当前读取器支持范围：拒绝打开并给出所需版本，不做猜测。
3. 版本在支持范围内但低于写入版本：只读打开，写入前必须迁移。
4. 校验失败：派生文件丢弃；权威文件进入隔离流程，不自动覆盖。

版本字段从一开始就在所有新文件头中预留，即使当前写入版本固定为 1。

### 组件版本与集合版本

`generation.bin` 保存集合聚合版本和每个组件的版本映射。聚合版本描述语义组合，组件版本描述物理编码。二者同时存在的原因是：同一个集合可以只迁移 payload 文件而不改变 WAL 编码，也可以为了字段索引升级只重建一个段。

打开时必须满足：

- 所有服务文件的组件版本都属于该 generation 声明的允许范围。
- 任一组件版本缺失时，若该组件是权威文件则拒绝打开；若是派生文件则允许重建。
- 聚合版本不能单独作为兼容依据；它只用于快速判断是否需要迁移。

### 能力位

文件头和 generation manifest 预留能力位，用于声明可选能力：压缩算法、向量类型、id 编码、索引类型、WAL 校验算法。读取器通过能力位判断能否解释文件，而不是通过集合版本做隐式推断。

能力位只允许追加，不允许赋予旧位新的含义。废弃能力位保留定义但不再写入。

## 兼容性策略

### 读取兼容

当前版本读取器可以打开较低版本的 collection，但打开前必须通过版本矩阵检查。版本矩阵由代码内的迁移注册表生成，不手工维护第二份配置。

派生文件即使版本可识别但结构验证失败，也只丢弃该文件并回退到 exact scan；权威文件验证失败则进入隔离目录，等待显式恢复。

### 写入兼容

只有当所有组件版本都是当前写入版本时才允许写入。只读打开的低版本集合必须先完成迁移才能接受写事务。这样避免同一 generation 内出现“部分文件旧格式、部分文件新格式”的隐式状态。

### WAL 兼容

WAL 段头包含自身版本和随机 CRC seed。重开时允许按段版本选择对应解码器，但新记录只写入当前版本的新段。旧段保持只读直到被完整 ACK 回收。

旧段和新段的索引空间必须连续。迁移时在旧段末端写入一条格式切换标记，声明旧格式的最后 LSN；新段名必须与该 LSN 严格衔接。段连续性校验跨版本仍然有效。

ACK 文件同时记录 generation、LSN 和 WAL 格式版本。generation 不匹配或 ACK 版本与待回收段版本不匹配时，ACK 视为无效。

### 快照兼容

快照清单记录 collection 聚合版本、每个文件版本、能力位和 CRC。恢复时优先按目标版本转换到当前写入格式；无法转换时拒绝恢复，不生成半迁移目录。

旧快照在未来版本中保持只读支持一段时间；支持窗口结束后从注册表删除对应迁移器，而不是在代码里保留不可验证的兼容分支。

## 迁移执行模型

### 权威文件迁移

权威文件不原地转换。迁移流程为：

1. 持有集合锁和维护锁，注册 WAL ACK pin，阻止日志被回收。
2. 读取旧 generation 的权威状态和尚未 ACK 的 WAL。
3. 在 staging 目录按新格式写完整 generation，逐文件 fsync 并校验。
4. 写出新的 generation manifest，其中包含迁移后的聚合版本和组件版本。
5. rename 发布 manifest，切换内存句柄。
6. 用新 generation 绑定 WAL，写入格式切换标记，推进 ACK 并回收已覆盖的旧段。

任何步骤失败都不得保留混合状态：manifest 发布前丢弃 staging；manifest 发布后进入 poison，必须重开并完成恢复确认。

### 派生文件迁移

索引、过滤位图、字段索引和量化文件在迁移时优先丢弃重建，而不是逐字节转换。只有重建代价高的 immutable 索引才提供迁移器，并且迁移结果必须与直接重建结果做一致性校验。

派生文件迁移失败只移除加速能力，不影响数据可读性。

### WAL 迁移

WAL 不重写历史段。打开低版本 WAL 时，先按旧解码器读取到格式切换标记，再按新解码器读取后续段。若没有切换标记但存在新版本段，视为损坏。

新格式段使用新的 CRC seed 和 8 字节对齐记录。旧段的 torn tail 只允许出现在最后一个旧段，且必须在格式切换标记之前；切换标记之后的 torn tail 按新格式规则处理。

### 快照迁移

恢复旧快照时先验证完整清单，再在 staging 目录转换为当前 generation；转换完成后才创建目标集合目录。目标目录的 generation id 从新 manifest 开始，不沿用快照中的旧 id。

快照中的 WAL 段按各自版本读取和重放；恢复完成后写当前版本的 ACK。旧 ACK 的 generation 不匹配时视为零。

## 迁移注册表

代码内维护一份迁移注册表，注册项描述源版本、目标版本、适用组件、是否可就地转换、预计资源需求和故障恢复策略。

打开流程根据注册表生成迁移路径：

- 存在路径：进入只读模式并执行迁移。
- 存在多个路径：选择步骤最少且经过验证的路径，不允许运行时猜测。
- 不存在路径：返回明确的“不支持的版本”错误。

注册表同时用于生成兼容性文档和启动时的版本校验，避免文档与实现漂移。

## 失败恢复语义

- 崩溃在 staging 写入期间：旧 generation 完整服务，staging 被忽略和清理。
- 崩溃在 manifest 发布后、句柄切换前：重开时按新 manifest 校验 staging 结果；不完整则进入隔离恢复，不回退到旧 manifest。
- 崩溃在 WAL 格式切换标记写入后、ACK 前：重放旧段和新段，直到 generation 水位；重复标记是 no-op。
- 崩溃在 ACK 后、旧段回收前：旧段因 generation 或版本绑定不匹配被忽略。
- 崩溃在任何 fsync 失败点：不推进 manifest、不推进 ACK、不截断日志。

核心原则是：generation manifest 仍是唯一提交点；WAL 是恢复权威；派生文件永远可重建。

## 启用阶段

### 当前阶段

保持版本 1，不做向后兼容。所有新文件头预留版本和能力位，但拒绝非版本 1 的权威文件。派生文件仍按当前规则失败时丢弃或隔离。

### 准备阶段

补齐所有文件的版本头、能力位和 CRC 覆盖边界；把版本判断集中到单一模块；新增迁移注册表框架但不注册实际迁移器。此阶段不改变现有文件格式语义。

### 验证阶段

在测试目录中人为生成旧版本 generation、WAL 和快照，验证只读打开、迁移路径选择、崩溃注入和迁移后逐点一致性。迁移器只允许在这个阶段之后逐步加入。

### 首次真实升级

选择一次低风险格式变化作为第一个迁移器，例如 payload 压缩方式或字段索引文件布局。上线前确认回滚策略：新版本写入的文件不承诺被旧版本读取，回滚必须使用升级前快照。

### 清理阶段

删除超过支持窗口的迁移器和旧格式读取路径。删除前确认没有仍在服务或可恢复的快照依赖它们。

## 验证矩阵

- 文件版本过高、过低、缺失、magic 错误、CRC 错误。
- 聚合版本与组件版本不一致。
- 能力位未知、能力位组合不支持。
- WAL 旧段到新段的边界、格式切换标记丢失、旧段 torn tail、新段 torn tail。
- generation 发布前、发布后未切换、ACK 前、ACK 后未截断、截断中崩溃。
- 旧快照恢复到新目录、新快照恢复到旧读取器、快照清单版本不匹配。
- 派生文件迁移结果与直接重建结果逐点一致。
- 每次迁移后的搜索、scroll、payload、字段索引和 ANN 结果与迁移前一致。
