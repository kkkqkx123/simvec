# simvec WASM 剩余任务分阶段方案

背景：浏览器形态已跑通检索小闭环，常驻内存、无持久化。`memory_engine` 实现了写入、过滤删除、载荷合并与索引声明等能力，但 `wasm_api` 与 `bindings/wasm` 只透出子集；`binding-matrix.md` 尚无 `wasm` 列。持久化、事务、错误契约、矩阵对齐均为剩余项。

总原则：只改原模块，不立替代模块；新能力按职责归位，内存语义归内存引擎，穿越形状归边界，宿主适配归 `JS` 包。默认保持版本一，不做历史兼容。验证按阶段收敛，每阶段最多一次编译检查加一次烟囱，输出先落文件再读。

## 补齐已实现未透出的边界

目标是让边界与内存引擎现状对齐，不新增语义。范围是集合配置读取、批量删除、过滤删除、载荷合并与单字段直写、分页下一页标记、指标快照与压缩计数、索引构建存在性等兼容桩，以及便捷向量查询。便捷查询放在 `JS` 侧组装通用查询后透传，保持 `Rust` 侧单一查询入口。分页返回需同时带出点位数组与下一页标记，与本机二元组语义一致。改动只触及原边界文件与原 `JS` 包装文件，类型声明随之更新。验收以主机特性编译通过与现有烟囱扩展为准，明确标注运维类接口在浏览器形态下为语义兼容空操作。

## 统一事务错误与穿越形状

目标是消除两形态的隐性分叉。内存引擎按集合分组顺序应用一批操作，单集合失败即停并返回首错，不做跨集合原子承诺，与本机逐集合提交的对外描述保持一致。错误统一为携带数字码与文本的异常形状，沿用现有七个具名划分，其余降级为基类。计数、存在性、布尔返回统一为宿主原生类型，集合列表、查询结果、载荷索引统一为解析后结构，避免字符串套字符串。关闭语义与是否关闭查询、重复关闭幂等与现有 `JS` 绑定一致。改动仍只改原模块，错误映射逻辑各自归位不跨层复制。验收为错误分支单测加烟囱中断言错误类型与关闭幂等。

## 会话快照与受控持久化

目标是让调用者可自理持久化，引擎本身不持有文件句柄。`Rust` 侧提供整库导出与整库导入，内容为集合配置与点位数组的版本一快照，复用已有序列化形状，维度与非有限校验与写入路径相同，导入时先校验后替换。`JS` 侧提供可选的持久适配器，优先使用浏览器持久目录做原子写，配额不足或接口缺失时回落纯内存并如实报错，不做静默降级。写入策略为显式保存与显式加载，不设后台自动同步，避免与单线程语义冲突。运维类的提升备份与重放恢复不进入该阶段。验收为导出导入往返单测、损坏快照拒绝单测、适配器缺失接口时的回落用例。

## 矩阵文档与发布对齐

目标是让矩阵如实反映 `wasm` 列。按生命周期、集合、写入载荷、事务、读取、维护指标、默认配置、错误映射的既有分组逐项标注已支持、兼容空操作、按设计缺席三态，不改三端既有列。同步更新 `wasm` 包自述的构建命令、产物目录、浏览器线程与内存规模约束，以及纯代码包加调用者构建产物的分发说明。烟囱扩展到与三端对等的全链路，另加关闭幂等与损坏输入用例。已有本机测试不重写。验收为矩阵与自述合入、主机特性编译与烟囱一次通过，`wasm32` 目标编译作为有网络环境下的附加门禁。
