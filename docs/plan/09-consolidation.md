# 剩余任务 09：整合清单与收尾补齐

基于 `docs/plan/README.md` 与 06、07、08 的验收口径，对当前工作区差异做一次整合，明确已闭环与本轮真正要补的代码。

## 已闭环

- 持久化与一致性：协调事务经各存储提交门闩落 WAL，载荷改写按槽原子提交，快照与截断同门闩，种类与具名具备压实与容量准入，内存后端拒绝非单稠密配置与查询。
- 领域统一：点与查询统一为空间映射，具名空间允许稠密稀疏多向量，具名拒绝 ANN 与量化，保留 FFI 稠密便捷字段。
- 稀疏：维度开放为 `u32` 空间，校验与输入顺序无关，写入与查询双侧归一，倒排权重累加加范数缓存，过滤下推与 TopK 截断已接入两侧精确扫描，全扫阈值经评估后明确不引入。
- 具名：单目标回传完整映射，融合自然全量，全量写入加单空间增量覆盖，删除收敛为整点删除。
- 接口：C ABI 新增具名增量更新并同步头文件，Python 与 JS 具备薄封装，Go、Java、R 与 Wasm 保持通用 JSON 透传。

## 本轮要补的代码

- C ABI 回归：在现有 `src/c_api/tests.rs` 内补具名增量更新的端到端用例，覆盖全量建集合、全量写入、单空间覆盖成功、回传完整映射，未知空间按预期失败。验证头文件声明与 Rust 侧一致，默认构建不受影响。
- Python 类型桩：在现有 `bindings/python/simvec/engine.pyi` 内补新增辅助的声明，与实现签名保持一致，不新增运行时逻辑。
- JS 类型声明：在现有 `bindings/js/src/engine.d.ts` 内补新增辅助的声明，与实现签名保持一致。
- Go 薄封装：在现有 `bindings/go/engine.go` 内补具名增量更新与具名稀疏查询的透传封装，复用已有 JSON 通道与 `simvec.h` 声明，不新增传输格式与距离逻辑。

## 明确不做的事项

- 不新增按空间删除向量：会破坏全量映射不变式，检索侧对缺失空间的语义无定义，整点删除已满足需求。
- 不引入全扫阈值与 posting 压缩：无全局统计支撑阈值判断，压缩与 `Idf` 不在本轮范围，权重非负前提保持。
- 不把种类与具名接入后台维护线程：后台语义为稠密专属，手动压实为正式接口，快照截断阈值继续生效。
- 不抽取种类与具名的统一基类：载荷形状不同，统一只增加分支，已复用评分与截断辅助。
- Java、R 与 Wasm 不新增专用封装：三者已有通用批量写入与查询 JSON 透传，可直接表达统一字段，Python、JS 与 Go 的薄封装已可作为用法示例，避免为每语言重复距离与校验逻辑。

## 验收

- 新增 C ABI 用例通过，`cargo test --all-targets --features c_api` 通过。
- Python 与 JS 类型检查口径与实现一致，Go 封装经代码走读确认复用已有通道。
- 文档中不再出现与实现矛盾的能力描述。
