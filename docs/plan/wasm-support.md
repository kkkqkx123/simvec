# simvec WASM 支持设计方案

背景：现有 `Python/JS/Go` 绑定都依赖本机动态库与文件系统，`JS` 绑定还要求 `Node FFI`。浏览器主线程、`WebWorker`、浏览器扩展与禁 `native` 的受控插件宿主无法 `dlopen`，也无 `POSIX` 文件语义。需要一种可在浏览器内运行的形态，与现有本机形态并存。

## 目标

保留本机形态不变，新增浏览器内存形态。两者共享类型、距离与过滤语义，共享 `JSON` 穿越形状，共享查询评分契约。`WASM` 形态只做会话级中小规模精确检索，不承诺 `WAL` 持久化、`mmap` 零拷贝、后台维护与并行建图。

## 两种形态划分

本机形态是当前行为：分段 `mmap` 向量文件、`WAL` 按批刷盘、提交队列单线程串行、后台维护线程、`rayon` 并行搜索与建图、`tokio` 多线程桥接。

浏览器形态是新增行为：无文件系统、无后台线程、无并行运行时、无 `mmap`。集合常驻内存哈希表，写入直接应用并返回，检索为线性精确扫描，距离核固定走标量路径，配置中的索引与量化段仅做形状兼容，不做加速。

形态切换走条件编译。语言无关的纯模块常驻两端；文件与线程相关模块仅进本机目标；内存引擎与 `WASM` 边界仅进 `wasm` 特性。主机加特性可同时编译两形态做对照，`wasm32` 目标默认只进浏览器形态。依赖按目标拆分，本机独占 `mmap` 与并行库，`WASM` 胶水库仅随特性引入。

## 复用结论

类型、距离评分、过滤求值、错误枚举四部分直接复用，不复制逻辑。`C API` 的三条边界约定平移到 `WASM` 边界：复杂值走 `JSON` 文本复用已有序列化形状，向量走连续单精度数组，方法返回统一错误文本。方法命名按宿主习惯映射，`Rust` 侧保持蛇形，`JS` 侧保持小驼峰。

## 包结构

`Rust` 侧新增内存引擎与 `WASM` 边界两个职责单元。内存引擎只依赖标准库与已有纯模块，提供集合管理、写入、读取、载荷、检索子集。`WASM` 边界是内存引擎的薄封装，负责 `JSON` 编解码与 `JS` 值转换，不做检索逻辑。`bindings/wasm` 是纯 `JS` 包，负责加载 `wasm-pack` 产物并暴露与现有 `JS` 绑定同形的类，动态库定位改为 `pkg` 目录查找。

## 接口取舍

首版只收敛检索闭环必需的集合、写入、读取、检索、分页、载荷读写与载荷索引声明。索引构建、量化构建、压缩、排空、维护扫描在浏览器形态下为语义兼容的空操作，返回未生效或存活数，不抛错。发布备份、临时集合提升、引擎级默认配置等运维能力暂不进入浏览器形态。缺失能力由文档明示，不做静默降级之外的第二套语义。

## 测试策略

`Rust` 侧以主机特性编译验证两形态共存，以 `wasm32` 目标编译验证浏览器形态独立可构建。内存引擎单测覆盖维度校验、非有限拒绝、过滤删除、分页与评分单调。`JS` 侧烟囱覆盖创建、写入、检索、载荷索引声明全链路，运行前需先做 `wasm-pack` 构建。已有本机测试不为 `WASM` 重写。

## 打包分发

`Rust` 主包默认不带 `WASM` 胶水，保持纯 `rlib` 构建。`wasm` 特性仅在需要浏览器产物时开启。`bindings/wasm` 仅发布纯 `JS` 包，`wasm` 二进制由调用者构建并指定路径。把二进制内嵌进包属于后续发行工作。

## 实施步骤

先合入条件编译依赖拆分与模块门控，再落内存引擎与 `WASM` 边界并通过双形态编译，最后补 `bindings/wasm` 包骨架、自述与烟囱。矩阵文档在形态稳定后再补列。

## 风险

浏览器形态无持久化，刷新即失，需调用者自理快照。线性扫描只适合中小规模，大库仍走服务端。`tokio` 多线程特性在 `wasm32` 下仅编译通过，运行时不使用。`wasm-pack` 构建需要网络与目标工具链，离线环境以主机特性编译做门禁。
