# simvec C API 与 Python 绑定设计方案

背景：`simvec` 目前只提供 Rust 原生 API，需要给 C 侧稳定 ABI，并基于该 ABI 提供 Python 绑定。C API 的做法参照 `~/code/linkrs` 的 `embedded/c_api` 模式，并按 `simvec` 的同步引擎特点做减法。

## 目标

对外提供一份 C 头文件与动态库，覆盖集合管理、写入、检索、载荷、索引维护全链路；Python 通过 `ctypes` 直接调用该动态库，不引入新的 Rust 依赖。C API 是唯一的稳定边界，未来其它语言绑定与高性能 Python 原生扩展都构建在它之上。

## 复用 linkrs 的五条模式

句柄不透明化：C 侧只见前向声明的 `simvec_engine_t`，内部是堆上的引擎句柄，`open` 负责装箱，`close` 负责拆箱回收。

错误码加文本：所有入口返回整型状态码，成功为零；最近一次错误的文本通过专门的取错函数以新分配字符串形式交还调用者释放。`open` 阶段尚无句柄时的错误走线程局部存储。

复杂类型走 JSON：集合配置、查询、过滤器、载荷、检索结果全部以 JSON 文本穿越 FFI，Rust 侧直接复用已有的 `Serialize/Deserialize` 实现，不在 C 侧为每个结构建模。

内存归属单一：入参一律借用，调用者保留所有权；出参一律由库分配，调用者用统一的释放函数归还；出错时输出指针必须置空。

头文件自动对齐：`cbindgen.toml` 描述生成规则，`build.rs` 仅在 `c_api` 特性开启且本机存在 `cbindgen` 时重生成 `include/simvec.h`，缺失时只告警不阻断离线构建。

## 与 linkrs 的差异

`simvec` 引擎是同步的，C 入口直接调用引擎方法即可，不需要 `linkrs` 那套为异步协调器准备的独占运行时桥接。错误体系也更简单，只映射 `VectorSearchError` 一个枚举，不需要扩展错误码。

## C API 结构

新增 `src/c_api` 模块，按职责拆分为错误、类型、引擎生命周期、集合、写入、读取、维护七个单元，另有一个测试单元覆盖空指针、非法 JSON、正常往返三类行为。`crate-type` 增加动态库与静态库输出，`c_api` 特性门控整个模块，默认构建不受影响。

点标识统一按字符串传递，靠现有的字符串到点标识的归一化逻辑自动区分数字与 UUID 形态。向量数据用连续单精度浮点指针加长度传递，载荷与过滤器用 JSON 对象字符串传递。

函数分组：生命周期负责打开关闭与取错释；集合分组负责创建删除与信息查询；写入分组覆盖单条与批量写入、按标识删除、按过滤器删除、载荷整体替换与字段合并、载荷索引建删；读取分组覆盖查询、便捷向量查询、单点读取、计数、分页扫描；维护分组覆盖索引构建丢弃、量化构建、存在性查询、压缩、待处理队列排空、指标快照与维护扫描触发。

调用约定：空指针与非法 UTF-8 一律返回误用码；调用者传入的 JSON 解析失败视为调用方错误；引擎返回的错误按变体映射到对应状态码并附带原文；涉及存在性的读取在缺失时返回未找到而非空结果。

## Python 绑定

首版采用 `ctypes` 薄封装，不新增任何 Rust 依赖。包结构分为原生加载器、错误映射、引擎封装三部分，加载器按环境变量优先、包相对路径次之的顺序定位动态库。配置、过滤器、载荷在 Python 侧就是字典，序列化后透传；向量接受任意浮点序列，内部转为连续单精度数组后传递指针。

`Engine` 类提供上下文管理，方法与 C API 一一对应，状态码非零即按码抛对应的异常子类。便捷查询默认返回载荷不返回向量，需要完整查询语义时走查询字典通道。

发布策略：Python 包本身是纯代码包，动态库由 Rust 构建产物提供，测试与示例通过环境变量指向本次构建的库文件。把动态库打进轮子属于后续发行工作，不在本阶段完成。

## 实施步骤

先合入文档与 C API 实现并通过特性门控编译；再补齐手写头文件与 Python 包骨架；最后用一次特性构建加一次 Python 烟囱验证覆盖全链路。

## 风险

引擎的线程安全已有后台维护线程共用存储句柄的事实作证，实现中再加编译期断言锁定。恐慌不能穿越 FFI，每个入口统一捕获并转为内部错误。删除集合时先等已排队的维护任务静默再删目录，避免与派生文件写入竞态；超时后仍如实返回错误。头文件在 `cbindgen` 缺席期间靠人工对齐，待工具有售后用生成结果做一次差异比对。
