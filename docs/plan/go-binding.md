# simvec Go 绑定设计方案

背景：C API 与动态库边界已经稳定，`include/simvec.h` 与 `src/c_api` 对照一致，共 50 个导出函数。Python 与 JavaScript 绑定均已实现为纯代码包，直接调用该动态库，方法与 C API 一一对应，另有功能矩阵记录三端对齐关系。本方案为 Go 补充同等级别的绑定，不改动 Rust 侧与 C ABI，只新增 `bindings/go` 纯 Go 模块。

## 目标

提供与现有两绑定功能对等的 Go 包：集合管理、写入与载荷、事务、读取检索、维护指标、引擎级默认配置全覆盖，错误语义与资源管理习惯与现有绑定保持一致。包内不携带编译好的动态库，调用者先构建 Rust 产物再编译或运行 Go 代码。首版保持薄封装定位，复杂类型继续走 JSON 文本，向量走连续单精度数组。

## 对现有架构的复用结论

句柄不透明化沿用现有做法：Go 侧只保存原生指针，不窥探引擎内部，打开时装箱，关闭时回收。错误处理沿用状态码加文本的做法：每个入口返回整型码，成功为零，失败时再取最近错误文本组装异常，打开阶段无句柄时的错误走线程局部存储对应的取错入口。

内存归属沿用单一规则：入参一律借用，调用结束后 Go 侧即释放临时分配；出参一律由库分配，Go 侧在读取后统一调用释放入口归还，调用者不直接接触释放函数。数据穿越沿用现有划分：配置、过滤器、载荷、查询走 JSON 文本，直接复用 Rust 侧已有的序列化形状，向量走连续单精度数组。类型化异常沿用现有划分：七个状态码具名映射，其余统一降级为基类异常并保留数字码。资源管理沿用可重复关闭加兜底回收的做法。测试沿用烟囱全链路对等的思路，Rust 侧已有的空指针与非法输入回归测试不需要在 Go 侧重复。

## 关键选型

调用机制选用 cgo，而不模仿 Python 的 ctypes 或 JavaScript 的 node:ffi 做运行时动态加载。原因是 Go 具备编译期外部函数接口，声明期即可对照头文件做类型检查，字符串、指针、输出参数的转换写法也更直接。代价是调用者需要启用 cgo 并具备 C 工具链，这一点在文档中明示，与现有两绑定零依赖的定位差异也如实写进自述。

模块路径与现有包名保持对应，包名为 simvec，对外只暴露引擎与错误两类概念。Go 方法名采用首字母大写的驼峰写法，与现有绑定的下划线与小驼峰写法按各自语言习惯分别映射，映射表写入自述后不再需要阅读源码确认。

首版不在 Rust 侧新增任何函数与依赖。现有 50 个导出函数已覆盖全部引擎能力，矩阵中记录的三端齐备分组可直接平移到 Go，不存在需要补 C API 的缺口。

## 包结构

新增顶层目录 `bindings/go`，内部按职责分为引擎封装、错误映射、模块说明、自述与冒烟测试五个部分。引擎封装负责句柄持有、参数编解码与出参回收，是唯一接触 cgo 声明的位置。错误映射负责状态码到异常类型的对照，只覆盖既定的七个具名码。模块说明记录构建约束与动态库定位方式。自述记录方法对照表与错误划分。冒烟测试覆盖全链路，不引入第三方依赖。

头文件引用指向工作区已提交的 `include/simvec.h`，避免在 Go 侧重复声明签名。头文件在生成工具缺席期间靠人工对齐的现状保持不变，Go 侧跟随该头文件，不自建第二份声明源。

## 接口映射策略

生命周期提供构造与关闭：构造接受目录路径，失败时读取无句柄错误文本；关闭可重复调用，关闭后的方法调用返回误用错误而非崩溃；另提供显式关闭状态查询与终结器兜底，终结器只做最后保障，不替代显式关闭。最近错误码与错误文本以只读访问方式暴露，用于捕获异常后的日志记录。

集合分组、写入与载荷分组、事务分组、读取分组、维护分组、引擎默认配置分组全部逐一映射，语义与现有两绑定一致：存在性查询返回布尔值，删除载荷索引返回是否命中，构建索引与构建量化返回是否生效，过滤删除与压缩返回计数，查询与读取返回解析后的结构，默认配置在未设置时返回空。点标识统一按字符串传递，调用者传入整数标识时先转字符串。分页扫描的偏移量保持可选，空值表示从头扫描。

向量参数的主形态定为单精度浮点切片，直接取首元素指针传递，空切片按误用处理。调用者持有双精度数据时由绑定层复制转换为单精度，转换语义在自述中写明。载荷、配置、过滤器、查询的输入形态定为通用映射或任意可序列化值，绑定层统一序列化为 JSON 后透传；输出的 JSON 文本由绑定层解析为通用结构返回。便捷向量查询保留过滤器、分数阈值、载荷与向量开关四个参数，需要完整查询语义时走查询字典通道。

并发语义定为引擎实例可并发调用，关闭操作除外。Rust 侧句柄已有互斥保护最近错误状态，Go 侧只需保护关闭状态本身，避免关闭与调用竞态。后台维护线程与存储句柄的共享关系已由引擎保证，Go 侧不另加全局锁。

## 错误映射

基类携带数字码与文本，七个具名子类分别对应未找到、已存在、非法配置、非法维度、误用、容量超限、过滤器错误。映射表与现有两绑定完全一致，基类兜底的状态为通用错误、内部错误、内存不足、输入输出错误、数据损坏、非有限数值。每个非零返回码在取错文本后立即映射抛错，成功路径不保留旧错误。打开失败因无句柄可查，改为读取线程局部错误文本后映射。另提供按码判断的辅助能力，便于调用者做分支处理而不依赖字符串匹配。

## 动态库定位与构建

构建期通过编译器与链接器搜索路径指向 Rust 产物，运行期通过系统库搜索路径定位同名动态库。文档推荐的配对做法是先做特性构建再编译运行 Go 代码，调用者保持绑定与动态库来自同一检出。平台差异只体现在动态库后缀上，查找顺序覆盖常见构建输出目录，找不到时给出明确的缺失提示而非链接期乱错。启用 cgo 与 C 工具链作为前置要求写进自述，与 Python 和 JavaScript 自述中的环境变量写法形成对照。

## 测试策略

冒烟测试与现有两绑定场景对等，分为三个用例：集合全链路、批量与过滤删除加事务加压缩、临时集合提升与默认配置读写。每个用例使用临时目录隔离，覆盖写入、读取、载荷索引、索引与量化维护、事务、提升、默认配置全链路。另补充错误映射用例验证未找到错误的具名类型，补充重复关闭用例验证关闭幂等，补充小规模并发读写用例验证并发语义。Rust 侧已覆盖的空指针与非法输入行为不在 Go 侧重复断言。

## 打包分发

Go 模块本身是纯代码模块，不携带动态库，与现有两绑定仅发布纯代码包的策略一致。把动态库打进发行产物属于后续发行工作，不在本阶段完成。自述统一推荐命令与路径写法，保持调用者自行构建并指定的模式。功能矩阵在 Go 落地后新增一列，标注四端对齐关系。

## 实施步骤

先落包骨架与错误映射并通过编译；再逐分组补齐引擎方法并保持与头文件签名一致；最后补自述、模块说明、方法对照表与冒烟测试，用一次特性构建加一次冒烟验证覆盖全链路。矩阵文档在方法齐备后同步更新。

## 风险

编译期依赖 C 工具链，部分精简环境需要额外安装，这一点需在自述前置说明。头文件在生成工具缺席期间靠人工对齐，Go 侧跟随该头文件，待工具有售后用生成结果做一次差异比对。整形宽度需要按头文件逐项核对，避免输出参数在不同平台上的截断。双精度调用者的精度转换需文档明示，避免静默截断引发检索困惑。终结器只做兜底，长期不显式关闭仍可能延迟回收，文档需强调显式关闭。
