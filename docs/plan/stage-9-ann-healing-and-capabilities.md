# 阶段九细化方案：ANN 高级能力与文档同步

对照 `docs/plan/storage-gap-remediation.md` 阶段九与问题清单中“其他索引与检索能力”一节。
本文只描述职责、状态转换和验证边界，不展开完整实现代码。

## 对照 qdrant

qdrant 在删除后对 HNSW 邻接做局部 healing，按 payload 分布建立 payload block，
并把向量类型扩展到 f16/uint/binary/turbo 与 multivector。simvec 已有按段发布的 HNSW /
IVF / 量化文件、段损坏隔离、过滤位图与量化图遍历；删除只置墓碑，邻接在压实前不做
局部修复，稀疏规划也缺少文档频率统计。

本轮实现局部图 healing 与基于文档频率的稀疏路径选择，并把已实现的格式和能力边界
同步到项目说明。压缩邻接分层加载、f16/uint/binary/turbo 与 multivector 属于后续评估项：
它们会改变持久化格式和距离 kernel 契约，必须在 quick bench 与 `naive` 一致性基线齐备后
单独落地，不在本轮伪装成已完成能力。

## 职责划分

- 删除局部修复：`HnswIndex::heal_deleted` 只处理被删节点相邻的层。先从所有相邻节点
  的邻接表移除被删 slot，再用这些邻居自身的现有边和共享过被删节点的边作为候选池，
  按与插入相同的 diversity heuristic 重选每层邻居。
- 触发边界：dense 写路径在把 slot 置为墓碑后，找到覆盖该 slot 的已发布段图并调用
  healing。重放路径在 open 时还没有发布图，跳过这一步；从持久化图打开时墓碑过滤继续
  保证被删点不会被返回。压实仍按段重建图，是最终拓扑校正点。
- 派生索引契约：healing 只改内存邻接，不改写已发布的 `hnsw_seg_*.bin`；版本计数器
  在每次改写后递增，搜索的双读校验继续覆盖并发邻接变更。任意段图损坏或缺失都只让
  该段退回 exact scan。
- 稀疏规划：阶段七持久化的 posting 文档频率用于选择 posting 累积或全扫描。这是执行
  路径选择，候选仍经过同一过滤器、同一距离函数和同一高分优先分数转换。
- 量化与段图：量化码继续按 `quant_seg_*.bin` 与段图一起发布，`HnswQuantCtx` 在搜索时
  快照代码与 query，不持有 quant 写锁；本轮不改变这一契约。
- 文档同步：项目说明更新文件布局、字段索引持久化、增量快照和局部 healing 的边界，
  并修正单写者锁按 `(dev, ino)` 引用计数的描述。

## 状态转换

- 删除点 → 墓碑置位 → 相邻图节点移除旧边 → 局部重选 → 搜索跳过被删点。
- open → 加载段图 → 墓碑过滤与已有邻接共同决定遍历；healing 不参与回放。
- 压实 → 全量重写存活段图 → 代替多次局部修复的累积拓扑漂移。
- 段图损坏 → 丢弃该段加速 → 该段 slot 进入 exact-scan pending 集。

## 不变量

- 公开分数仍为高分优先，内部距离仍为低分优先；healing 不改变距离与分数计算。
- 派生索引损坏只降级该段，不影响正确性与候选覆盖基线。
- 过滤查询与未过滤查询共享同一后置过滤与分数转换；规划统计不参与资格判定。
- 新距离 kernel 若将来引入，必须先与 `naive` 在 1e-4 内一致。

## 验收

- 持续写入与删除后，邻接表不再指向被删 slot，探测结果不包含墓碑。
- 段图文件损坏隔离测试：坏段 exact-scan 回退，其它段仍走 ANN。
- 过滤查询与未过滤查询候选一致性测试沿用现有基线。
- 项目说明中的锁键、文件布局和能力边界与实现一致。
