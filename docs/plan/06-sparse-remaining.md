# 剩余任务 06：稀疏检索收尾

基于 `docs/plan/README.md` 问题 13、14、15 与本轮范围说明。
 dense 具名仍走精确扫描、稀疏权重仍要求非负、比较器仍只有 MaxSim 的前提保持不变。

## 现状

- 稀疏维度已开放为 `u32` 空间，写入侧经 `normalized` 排序后入库，候选打分已改为倒排权重累加加每槽范数缓存。
- `VectorData::validate` 仍用相邻窗口判重，隐含要求输入已排序。写入侧因先归一化而侥幸成立，查询侧未经归一化直接校验与打分，乱序带重复下标的查询会漏检重复并重复累加同一词项。
- 查询打分对稀疏与稠密统一走收集全部候选后全量排序。过滤条件在累加之后才生效，被过滤掉的点仍参与倒排累加。`limit` 很小而候选很多时仍付全排序代价。无全扫阈值选择。
- 稀疏查询范数为零时直接返回空候选，行为正确但与阈值过滤的交互未在文档中明确。

## 细化方案

- 类型层：在现有 `src/types/point.rs` 内原地调整稀疏校验。用集合语义判重，使校验与输入是否有序无关。保留非空、等长、有限、非负与维度上界检查，不放宽非负约束。归一化函数保持原地排序语义不变。
- 查询归一化：在 `src/kind_store/read.rs` 与 `src/named_store/read.rs` 的检索入口，对取出的目标载荷做一次归一化拷贝后再校验与打分。存储侧已归一化不受影响，查询侧乱序唯一输入可直接检索，重复下标查询在校验阶段即被拒绝。
- 过滤下推：在两个精确扫描检索中，当查询携带过滤器时，先扫一遍存活槽得到允许集合，再将其传入倒排累加函数。累加函数在现有 `src/kind_store/score.rs` 内扩展，遇到不在允许集合的槽直接跳过。稠密与多向量仍走逐槽过滤，不新增索引结构。
- TopK 截断：在 `src/kind_store/score.rs` 内新增按偏移加截断的堆选择辅助，具名侧经 `src/named_store/score.rs` 复用。当需要的条数远小于候选总数时用线性选择加截断内排序代替全排序。排序的并列决胜规则保持槽号升序不变，结果分页语义不变。
- 全扫阈值：本轮不引入基于代价模型的扫表切换。倒排累加已是稀疏的最优路径，全扫只在查询词项极度稠密时才可能更优，而当前 posting 按词项分散存储，无全局统计支撑阈值判断。文档中明确记录该取舍，避免引入不可验证的启发式。
- 内存后端：在 `src/memory_engine/points.rs` 的检索入口显式拒绝非稠密目标，错误类型与创建集合时的拒绝保持一致。之前依赖维度不匹配间接报错，信息含糊。

## 验收

- 乱序唯一稀疏查询可检索，乱序带重复下标的查询在校验阶段失败。
- 带过滤器的稀疏检索结果与不过滤累加后再过滤一致，被过滤点不参与累加。
- 小 `limit` 大候选时仍返回与全排序相同的截断有序结果。
- 稀疏空查询与零范数查询行为不变，仍返回空结果而非错误。
- 内存后端对稀疏、多向量与具名查询返回明确的配置错误。
