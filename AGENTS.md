# AGENTS.md — simvec

Local vector search engine in Rust: HNSW-first ANN with exact-scan fallback, WAL durability, mmap storage, plus a C ABI (`--features c_api`) that all language bindings wrap. A separate Rust shell in `cli/` uses the public Rust API directly. `crate-type = ["cdylib", "staticlib", "rlib"]`, rust-version 1.97, edition 2021. Storage audit and hardening plan: `docs/plan/storage-audit-and-hardening.md`; qdrant comparison issue inventory: `docs/issue/storage-comparison-with-qdrant.md`; storage gap remediation stages: `docs/plan/storage-gap-remediation.md`; future version and migration design: `docs/plan/long-term/versioning-and-migration.md`; CLI design: `docs/plan/standalone-cli-shell.md`.

## Commands

- `cargo build` — plain rlib (no C ABI). `cargo build --features c_api` — C ABI / dynamic library (required before any binding test).
- `sh scripts/build-cli.sh` — standalone Rust shell; `cargo test --manifest-path cli/Cargo.toml --target-dir target` — shell tests.
- `cargo test -p simvec` — unit + integration tests.
- `cargo bench -p simvec` — criterion benches. `QUICK=1 cargo bench` — seconds-long smoke gear; QUICK vs full numbers (and numbers across machines) are never comparable.
- No rustfmt.toml / clippy.toml — defaults apply.
- `scripts/publish.sh [--dry-run]` — crates.io publish.

## Layout

`src/engine` (LocalVectorEngine, maintenance worker) · `src/storage` (CollectionStore: mmap vectors, segmented WAL, payloads, tombstones, search; plus `point_blobs` / `postings` used by the multi-space stores) · `src/index` (HNSW, IVF/kmeans, persist) · `src/distance` (AVX2/AVX-512/NEON/naive kernels) · `src/kind_store`, `src/named_store` (multi-space) · `src/c_api` + `include/simvec.h` · `src/memory_engine` + `src/wasm_api` (wasm feature) · `cli/` (standalone Rust shell: own Cargo package and lockfile) · `bindings/{python,js,go,java,r,wasm}` · `docs/binding-matrix.md` (capability matrix per binding, Chinese).

## Non-obvious rules

- **Test files are not auto-discovered.** Unit tests hang off modules via `#[cfg(test)] #[path = "..."] mod tests;`; top-level files are `src/<module>_tests.rs`. A new `*_tests.rs` does nothing until wired into its parent module with `#[path]`.
- **Score contract:** public scores are higher-is-better on every metric (conversion table in README); internal distances are lower-is-better. Cosine normalizes on the fly — `vectors.bin` must keep the original bytes.
- **`naive` is the correctness baseline.** New distance kernels must match naive within 1e-4. `simd_portable` currently delegates to naive (portable_simd is unstable).
- **`include/simvec.h` is committed.** `build.rs` regenerates it only when the `c_api` feature is on AND cbindgen is installed; otherwise the committed header is used silently. After changing `src/c_api`, rebuild with cbindgen present and commit the regenerated header, and update `docs/binding-matrix.md` plus the affected bindings.
- **Bindings:** every non-wasm binding is FFI over the built cdylib — `cargo build --features c_api` first, then point `SIMVEC_LIB` (or fallback paths under `target/debug|release`) at it. JS needs Node 22+ `--experimental-ffi`; Java needs `sh bindings/java/scripts/build-native.sh` then `mvn test`; R needs `R CMD INSTALL`; wasm needs the `wasm32-unknown-unknown` target and `npm run build` in `bindings/wasm`.
- **CLI boundary:** `cli/` is a separate Cargo package with its own lockfile and bin target `simvec`. It calls public `LocalVectorEngine` / `types` APIs directly; it does not use the C ABI, does not require `--features c_api`, and cannot reference private core modules. JSON command DTOs live in the CLI package and convert to public types.
- **`target_arch = "wasm32"` compiles out** `engine`, `storage`, `index`, `kind_store`, `named_store`, `c_api` (see `src/lib.rs` cfgs) — native-only code must stay behind those gates.
- **On-disk layout (per collection).** The collection root holds `generation.bin`, the shared `wal/`, a `.lock` file and a type marker (`meta.bin` is inside the data generation, not the root; `kind.bin` / `named.bin` stay at the root). All serving files live in `generations/g<20-digit id>/`; `.g*-staging/` is an unpublished build and is ignored on open. Dense generation files: `meta.bin`, `segments.json` (boundary plus per-segment live/tombstone/persisted accounting), `dense_snapshot.bin`, `keys.bin`, `vectors.bin`, `tombstones.bin`, `payloads_store/` (`config.json` with block/page geometry and payload compression, `tracker.bin`, `tracker.journal.bin`, `bitmask.bin`, `pages/page_*.bin`), `payload_indexes.json`, `field_indexes.bin` (CRC envelope with generation/lsn/capacity and posting contents), optional `quant.bin` / `quant_meta.bin`, per-segment `hnsw_seg_<start>.bin`, `ivf_seg_<start>.bin` and `quant_seg_<start>.bin` files. `dense_snapshot.bin` carries the id→slot directory with per-id applied lsn and tombstone slots; it is usable only when its generation id, lsn and slot geometry match `generation.bin` / `meta.bin`, otherwise open scans the files and replays from the manifest. Payload bytes come from the live `PayloadStore`, so payload-only writes after a checkpoint do not invalidate the id directory: WAL replay re-applies them. `kind` / `named` add `kind.bin` / `named.bin`, `points.bin` (append-only blob file: 4-byte-aligned records, 12-byte header, grown in 4 MiB chunks, truncated to the snapshot's `blobs_len` at open), `payloads.bin` (same blob format for JSON payloads, truncated to the snapshot's `payloads_len` at open or to zero when no snapshot is published), and `postings/` (bucket files keyed by `term >> 10`, records `[term u32][count u32][(slot u32, weight f32) * count]`, plus `manifest.bin` with bucket lengths, term chains and per-term document frequencies). Their snapshots keep only the `{slot, id, blob, payload_blob, norm}` directory; vectors and JSON payload bytes live in the blob files, vectors read through the zero-copy `VectorView<'a>`. A point's `payload_blob` is `None` exactly when its in-memory payload changed since the last checkpoint — the checkpoint appends new JSON only for those points. `bitmask.bin` and `tracker.bin` publish via tmp+rename+dir fsync; a pointer into a missing/short page is `CorruptData`. Dense payload page values store `[u32 CRC][u8 codec][data]` (`0` raw JSON, `1` LZ4) with the CRC covering codec plus data; legacy `[u32 CRC][JSON]` values still decode and are rewritten on next touch. `ValuePointer.length` includes the header and `max_payload_bytes` excludes it. Before the first checkpoint (`generation.lsn == 0`) a payload store that fails pointer/CRC validation is rebuilt from the WAL; after that the same damage is `CorruptData`. `tracker.journal.bin` records pointer changes between checkpoints; open replays higher-version records and truncates a torn tail; replay floor greater than zero additionally rolls back slots whose journal lsn is newer than the floor so WAL replay restores them. Checkpoint publishes the compact `tracker.bin` before clearing the journal. The bitmask is rebuilt from the tracker when damaged or when a live pointer's bit is free; orphaned used blocks are retained as harmless leaks.
- **Generation commits.** `generation.bin` (checksummed `{version, generation, lsn}`) is the commit point. Checkpoints flush in two passes (bulk without the queue gate so appendable segments keep receiving writes, then a gate-time re-sync of the raced tail), write `dense_snapshot.bin` and `field_indexes.bin`, publish `segments.json` with per-segment entries and per-segment persisted marks, then advance the manifest lsn and publish `wal/acked-lsn` clamped by live pins; any fsync failure aborts before the manifest and keeps the WAL intact. Compaction writes a whole new generation under `.g*-staging/`, fsyncs it, renames it to `g<id>`, publishes the manifest, then switches in-memory handles (`DataFiles` for dense, `ArcSwap` blob/postings for exact stores) and only then truncates the WAL. Once the manifest is published, any failure before the in-memory switch finishes poisons the store: reads continue, writes/checkpoint/compact are rejected until reopen. Dense readers load one `DataFiles` guard per search so vectors/keys/tombstones/payload/index never mix generations. Compaction's contended fallback stages under the queue gate from a read snapshot and takes the write lock only for the generation swap. Open ignores staging dirs and rejects a WAL ack newer than the manifest (dense) or a snapshot whose lsn differs from the manifest (kind/named). A dense snapshot ahead of the manifest is discarded, not treated as corruption.
- **The WAL is a directory.** `wal/<20-digit first-lsn>.bin` (segment format v2: 32-byte header with magic/version/random seed/first-lsn, 8-byte aligned records, chained CRC over length + payload + zero padding, zero length = preallocated slack); a txn never spans segments; segments are preallocated to `StorageConfig::wal_segment_bytes` (default 64 MiB) with a capacity-matched `.spare` prebuild consumed on rollover, served through mmaps with one `flush_range` per group-commit batch. Each dense store tracks per-segment applied/persisted LSNs and holds a `WalAckPins` registry; checkpoints and compaction truncate through the watermark clamped by the lowest live pin (unlink fully covered segments); `truncate()` is the full-wipe helper retained for test teardown, not a production compaction path. Both paths first publish `wal/acked-lsn` (CRC32-protected `{generation, lsn}`) and fsync the WAL directory; stores bind the log to their generation at open and after compaction publish, so an ack from another generation reads as zero. Dense replay uses the generation manifest lsn as its floor and skips records whose lsn is not newer than the per-id version water mark; exact-scan stores replay from the generation manifest lsn with `read_all_from`, never from the WAL watermark. A torn tail record is tolerated in the **last** segment only — damage anywhere else is `CorruptData`, never silent truncation. Rollover truncates the closed file to its valid prefix, so a torn tail can never be sealed into a middle segment. Replay also requires each closed segment's last lsn to be exactly one below the next segment name; gaps and overlaps are `CorruptData`, never silent skips. Checkpoint/compaction markers always carry freshly allocated LSNs (never the watermark). The commit-queue worker is the only bulk LSN assigner (rollback on flush failure, so no holes); slots are assigned at apply time in log order; payload WAL records are keyed by external point id and resolved through the id tracker on both live and replay paths.
- **Filter planning and snapshots.** `PayloadIndexManager::plan_filter` narrows candidates with `must` / `must_not` / `should` / `min_should` bitmaps; Numeric/Map/Text/Geo plus per-field shape indexes cover equality, ranges, tokens, radius/box, `IsNull` / `IsEmpty` / `ValuesCount`, and any unindexed clause disables that group's narrowing while the full filter still runs on every candidate. `field_indexes.bin` is derived: a generation/lsn/definition mismatch is discarded and rebuilt from payload bytes and WAL replay. Sparse named/kind spaces persist per-term document frequencies in `postings/manifest.bin` and use them only to choose posting accumulation versus full scan. `CollectionStore::snapshot_to` registers a WAL acknowledge pin over the copy window and copies the serving generation plus the whole WAL under the maintenance lock, queue gate and store read lock, and writes a CRC-checked `snapshot.json`; each entry carries file version, length and CRC. `snapshot_to_incremental(base, dest)` verifies the base snapshot and hard-links entries whose version/length/CRC all match, copying only changes; the result is still a complete self-contained tree. `verify_snapshot` validates lengths/CRCs and rejects escaping manifest paths; `restore_snapshot(src, dest)` copies a verified snapshot into a new directory and opens it to validate. The engine exposes dense snapshot methods; C ABI exposure remains a design item.
- **Single writer per collection.** All dense/kind/named `create`/`open` paths hold an advisory `flock` on the root `.lock` file for the store's lifetime. Handles in one process share the lock by `(dev, ino)` with a reference count, so promote/restore renames keep sharing it; another process opening the same directory fails immediately. The OS releases the lock on process exit.
- **Checkpoint order for `kind` / `named` is load-bearing:** `blobs.sync() → postings.flush(Some(lsn)) → checkpoint_payloads (append + sync) → snapshot::write → wal.truncate_through(lsn)`; every sync propagates I/O errors before the manifest advances. `postings/manifest.bin` must carry the same `lsn` as the snapshot; when they differ the dictionary is discarded and rebuilt from the snapshot, never patched incrementally. `points.bin` and `payloads.bin` are therefore **derived data** — `kind`/`named` WAL records still inline the full vector and JSON payload, so replay re-appends both kinds of blobs (WAL vector externalization remains a design item in `docs/plan/storage-audit-and-hardening.md`).
- **Scratch dirs** `*.rebuild-*`, `.old-*`, `.suspect-*` exist only for crash recovery and are never loaded into the serving registry — don't scan them in tests.
- HNSW and IVF are each built as one derived file per complete dense segment; segment-local ids map to global vectors through `slot_base`, and quantized codes are written to matching `quant_seg_<start>.bin` files. A corrupt or missing segment file only removes ANN acceleration for that segment, whose slots join the exact-scan pending set. Deleting a dense point locally heals the affected in-memory HNSW neighborhoods (the persisted graph is unchanged and tombstones still filter results); compaction remains the full topology repair. The partial tail stays in `pending` and is exact-scanned until a segment completes; drain and repair rebuild only the affected segment. HNSW promotion is automatic past `full_scan_threshold` (default 10 000); a background maintenance worker runs every 30 s. ANN and quantization apply only to the single default dense space — named/sparse spaces use exact scan; unsupported combinations are rejected at config time.
