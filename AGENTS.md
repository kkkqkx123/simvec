# AGENTS.md

Local vector search engine in Rust: HNSW-first ANN with exact-scan fallback, WAL durability, mmap storage; a C ABI (`--features c_api`) that all language bindings wrap. `cli/` is a separate Rust package that calls the public Rust API directly.

## Commands

- `cargo build` (plain rlib) / `cargo build --features c_api` (C ABI; required before any binding test).
- `sh scripts/build-cli.sh` builds the CLI; `cargo test --manifest-path cli/Cargo.toml --target-dir target` runs CLI tests.
- `cargo test -p simvec`; `SIMVEC_FAULT=<point>[,<point>] cargo test` arms a crash window (points in `src/storage/fault.rs`, matrix in `tests/fault_injection_test.rs`).
- `cargo bench -p simvec`; `QUICK=1` is a seconds-long smoke run — never compare QUICK vs full numbers or numbers across machines.
- No rustfmt/clippy config — defaults apply. `scripts/publish.sh [--dry-run]` publishes to crates.io.

## Layout

`src/engine` (LocalVectorEngine, maintenance worker) · `src/storage` (CollectionStore and sub-stores) · `src/index` (HNSW/IVF/persist) · `src/distance` (SIMD kernels) · `src/kind_store`, `src/named_store` (multi-space) · `src/c_api` + `include/simvec.h` · `src/memory_engine` + `src/wasm_api` (wasm) · `cli/` · `bindings/{python,js,go,java,r,wasm}` · `docs/binding-matrix.md` (per-binding capability matrix, Chinese).

## Non-obvious rules

- **Score contract:** public scores are higher-is-better on every metric (conversion table in README); internal distances are lower-is-better. Cosine normalizes on the fly — `vectors.bin` keeps the original bytes.
- **`create` validates element dtypes:** an encoding with no distance mapping (e.g. `Turbo`) is rejected at creation, not on first upsert.
- **`naive` is the correctness baseline:** new distance kernels must match it within 1e-4; `simd_portable` currently delegates to naive.
- **`include/simvec.h` is committed:** `build.rs` regenerates it only with `c_api` on and cbindgen installed, otherwise the committed header is used silently. After changing `src/c_api`, regenerate and commit the header, and update `docs/binding-matrix.md` plus affected bindings.
- **Bindings:** all non-wasm bindings are FFI over the cdylib — build with `--features c_api` first, then point `SIMVEC_LIB` (or fallback paths under `target/debug|release`) at it. JS needs Node 22+ `--experimental-ffi`; Java needs `build-native.sh` then `mvn test`; R needs `R CMD INSTALL`; wasm needs the `wasm32-unknown-unknown` target and `npm run build` in `bindings/wasm`.
- **CLI boundary:** separate Cargo package (own lockfile, bin `simvec`) using only public `LocalVectorEngine`/`types` APIs — no C ABI, no `c_api` feature, no private core modules. JSON DTOs live in the CLI package and convert to public types.
- **wasm gating:** `target_arch = "wasm32"` compiles out `engine`/`storage`/`index`/`kind_store`/`named_store`/`c_api`; native-only code must stay behind those cfgs.
- **On-disk layout (per collection):** root holds `generation.bin`, shared `wal/`, `.lock`, and a type marker. All serving files live in `generations/g<20-digit id>/`; `.g*-staging/` is an unpublished build and is ignored on open. Dense data is split into `segments/<start>/` (`vectors.bin` + `vector_dtype.bin`, `keys.bin`, `tombstones.bin`, `id_tracker.bin`, `payloads_store/`), plus derived `segments.json`, `payload_indexes.json`, `field_indexes.bin`, optional quant files, and per-segment `hnsw_seg_*`/`ivf_seg_*`/`quant_seg_*`. There is no generation-wide `dense_snapshot.bin`/`vectors.bin`/`keys.bin`/`tombstones.bin`. `kind`/`named` keep space config in the checksummed `spaces.json` inside the generation, with vectors/payloads under `spaces/<space>/segments/<start>/`, postings under `spaces/<space>/postings/`, and optional `spaces/<space>/ann/` for dense named spaces. Any commit file with bad magic/CRC is `CorruptData` — no legacy read path.
- **Generation commits:** `generation.bin` (checksummed `{version, generation, lsn}`) is the commit point. Checkpoints flush dirty segments in parallel; each segment fsyncs and advances its own persisted watermark independently; ACK is the minimum of all segment watermarks clamped by generation lsn and live WAL pins, then `wal/acked-lsn` is published. A single segment failure leaves generation and ACK unadvanced and marks maintenance unhealthy without poisoning writes. A visible tracker names only durable bytes by construction: entries newer than the segment frontier are published as unknown and re-derived by WAL replay; the gated section is publication only (tracker/`meta.bin`/`segments.json`/log marker), no data re-flush, and `gate_wait_ms` should stay in the millisecond range. Compaction writes a whole new generation under `.g*-staging/`, fsyncs, renames, publishes the manifest, switches in-memory handles, then truncates the WAL; failure after publish but before the switch poisons the store (reads only until reopen). Open ignores staging dirs and rejects a WAL ack newer than the manifest, missing/mismatched `spaces.json` or `vector_dtype.bin`, and tracker CRC failures.
- **The WAL is a directory:** `wal/<20-digit first-lsn>.bin`, with a 32-byte header, 8-byte-aligned records, chained CRC, and zero length meaning preallocated slack; a txn never spans segments; segments are preallocated to `wal_segment_bytes` (default 64 MiB). Replay scans records sequentially over mmaps, no separate index. Checkpoint/compaction truncate through the watermark clamped by the lowest live pin; `truncate()` is the full-wipe helper for test teardown only. Both paths first publish and fsync a CRC-protected `wal/acked-lsn`, and stores bind the log to their generation at open and after compaction. A torn tail is tolerated only in the **last** segment — damage anywhere else is `CorruptData`, never silent truncation; replay requires contiguous segment lsns, gaps/overlaps are `CorruptData`. Checkpoint/compaction markers always carry freshly allocated LSNs; the commit-queue worker is the only bulk LSN assigner (rolls back on failure, no holes).
- **Filter planning and snapshots:** `plan_filter` narrows candidates with `must`/`must_not`/`should`/`min_should` bitmaps; an unindexed clause disables that group's narrowing while the full filter still runs on every candidate. `field_indexes.bin` is derived — a version/lsn/definition mismatch is discarded and rebuilt. `snapshot_to` pins WAL acknowledgements over the copy window and copies the serving generation plus WAL under the maintenance lock and queue gate (not the store read lock), writing a CRC-checked `snapshot.json`; it uses `FICLONE` when supported and copies WAL segments to their valid prefix only. Incremental snapshots hard-link entries whose version/length/CRC match and still produce a complete self-contained tree. The C ABI exports all four snapshot functions, wrapped by the five native bindings; wasm uses its own OPFS JSON snapshot.
- **Single writer per collection:** every `create`/`open` holds an advisory `flock` on the root `.lock` for the store's lifetime; same-process handles share it by `(dev, ino)` with a refcount, another process fails immediately, and the OS releases it on exit.
- **`kind`/`named` checkpoint order is load-bearing:** `blobs.sync() → postings.flush(Some(lsn)) → checkpoint_payloads → snapshot::write → wal.truncate_through(lsn)`; each sync propagates I/O errors before the manifest advances. `postings/manifest.bin` must carry the same lsn as the snapshot or the dictionary is discarded and rebuilt. `points.bin`/`payloads.bin` are derived data; WAL records still inline the full vector and JSON payload.
- **Scratch dirs** `*.rebuild-*`, `.old-*`, `.suspect-*` exist only for crash recovery, are never loaded, and should not be scanned in tests.
- **Slot allocation is append-only:** overwriting an existing id allocates a new slot and tombstones the old, so complete segments only ever append and stay byte-identical. Allocation order: a free slot in the appendable tail first, then `meta.next_slot`; complete segments are never reclaimed (frozen garbage waits for compaction). The free list is derived and `free_cursor` resets at every durable boundary. `meta.next_slot` is a high-water mark, not a live count — admission and capacity use `live_count`. During replay an upsert of a known id writes back into the tracker's named slot to stay idempotent (slot numbers after an un-checkpointed replay may differ from the live run while directory/vectors/counts stay consistent).
- **Background compaction** is scheduled from per-segment garbage ratios; the appendable tail is excluded when a frozen segment sits in front of it, but a tail-only collection stays eligible. Compaction rewrites the **whole generation** and re-packs live slots into a dense prefix (`meta.next_slot = live_count`), so segment starts/capacities and every later slot range move and all ANN/quant files are rebuilt. Segment-level compaction (hard-linking untouched segments) is the next milestone, blocked on payload immutability (`PayloadStore::put_at` still rewrites pages in place).
- **HNSW/IVF** are built one derived file per complete dense segment; segment-local ids map to global vectors via `slot_base`; a corrupt or missing segment file only drops ANN for that segment (exact scan). Local deletes heal affected HNSW neighborhoods; a whole-store graph repair runs every 256 accumulated tombstones, and compaction is the full repair; the partial tail stays in `pending` and is exact-scanned until the segment completes. HNSW auto-enables past `full_scan_threshold` (default 10 000); the maintenance worker runs every 30 s. ANN tiers: the default dense space gets per-segment HNSW/IVF/quant files; a named dense space gets one graph at `spaces/<space>/ann/hnsw.bin` and **no** IVF or quantization (selecting IVF there silently means exact scan; multi uses MaxSim only); sparse spaces use postings plus exact scan, never ANN.
