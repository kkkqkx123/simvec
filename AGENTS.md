# AGENTS.md — simvec

Local vector search engine in Rust: HNSW-first ANN with exact-scan fallback, WAL durability, mmap storage, plus a C ABI (`--features c_api`) that all language bindings wrap. A separate Rust shell in `cli/` uses the public Rust API directly. `crate-type = ["cdylib", "staticlib", "rlib"]`, rust-version 1.97, edition 2021. qdrant comparison issue inventory: `docs/issue/storage-comparison-with-qdrant.md`; binding capability matrix: `docs/binding-matrix.md`; open storage work (incremental compaction, slot free list, blob ownership, validation matrix): `docs/plan/deferred-storage-completion.md`.

## Commands

- `cargo build` — plain rlib (no C ABI). `cargo build --features c_api` — C ABI / dynamic library (required before any binding test).
- `sh scripts/build-cli.sh` — standalone Rust shell; `cargo test --manifest-path cli/Cargo.toml --target-dir target` — shell tests.
- `cargo test -p simvec` — unit + integration tests.
- `cargo bench -p simvec` — criterion benches. `QUICK=1 cargo bench` — seconds-long smoke gear; QUICK vs full numbers (and numbers across machines) are never comparable.
- No rustfmt.toml / clippy.toml — defaults apply.
- `scripts/publish.sh [--dry-run]` — crates.io publish.

## Layout

`src/engine` (LocalVectorEngine, maintenance worker) · `src/storage` (CollectionStore: mmap vectors, segmented WAL, payloads, tombstones, search; plus `point_blobs` / `postings` used by the multi-space stores) · `src/index` (HNSW, IVF/kmeans, persist) · `src/distance` (AVX2/AVX-512/NEON/naive kernels) · `src/kind_store`, `src/named_store` (multi-space) · `src/c_api` + `include/simvec.h` · `src/memory_engine` + `src/wasm_api` (wasm feature) · `cli/` (standalone Rust shell: own Cargo package and lockfile) · `bindings/{python,js,go,java,r,wasm}` · `docs/binding-matrix.md` (capability matrix per binding, Chinese).

## Non-obvious rules

- **Test files are not auto-discovered.** Unit tests hang off modules via `#[cfg(test)] #[path = "..."] mod tests;`; top-level files are `src/<module>_tests.rs`. A new `*_tests.rs` does nothing until wired into its parent module with `#[path]`.
- **Score contract:** public scores are higher-is-better on every metric (conversion table in README); internal distances are lower-is-better. Cosine normalizes on the fly — `vectors.bin` must keep the original bytes.
- **`naive` is the correctness baseline.** New distance kernels must match naive within 1e-4. `simd_portable` currently delegates to naive (portable_simd is unstable).
- **`include/simvec.h` is committed.** `build.rs` regenerates it only when the `c_api` feature is on AND cbindgen is installed; otherwise the committed header is used silently. After changing `src/c_api`, rebuild with cbindgen present and commit the regenerated header, and update `docs/binding-matrix.md` plus the affected bindings.
- **Bindings:** every non-wasm binding is FFI over the built cdylib — `cargo build --features c_api` first, then point `SIMVEC_LIB` (or fallback paths under `target/debug|release`) at it. JS needs Node 22+ `--experimental-ffi`; Java needs `sh bindings/java/scripts/build-native.sh` then `mvn test`; R needs `R CMD INSTALL`; wasm needs the `wasm32-unknown-unknown` target and `npm run build` in `bindings/wasm`.
- **CLI boundary:** `cli/` is a separate Cargo package with its own lockfile and bin target `simvec`. It calls public `LocalVectorEngine` / `types` APIs directly; it does not use the C ABI, does not require `--features c_api`, and cannot reference private core modules. JSON command DTOs live in the CLI package and convert to public types.
- **`target_arch = "wasm32"` compiles out** `engine`, `storage`, `index`, `kind_store`, `named_store`, `c_api` (see `src/lib.rs` cfgs) — native-only code must stay behind those gates.
- **On-disk layout (per collection).** The collection root holds `generation.bin`, the shared `wal/`, a `.lock` file and a type marker (`meta.bin` is inside the data generation, not the root; `kind.bin` / `named.bin` stay at the root). All serving files live in `generations/g<20-digit id>/`; `.g*-staging/` is an unpublished build and is ignored on open. Dense data is split into physical segments at `segments/<start>/`: `vectors.bin` (fixed-stride f32 mmap; a `vector_dtype.bin` checksummed sidecar records the element dtype + affine params), `keys.bin`, `tombstones.bin`, `id_tracker.bin` (the authoritative id→slot directory with per-id applied/delete lsn), `payloads_store/` (block-based payloads: `config.json`, `tracker.bin`, `tracker.journal.bin`, `bitmask.bin`, `pages/page_*.bin`), plus derived `segments.json` (generation, boundaries, capacity, live/tombstone counts, per-segment applied/persisted lsn), `payload_indexes.json`, `field_indexes.bin`, optional `quant.bin`/`quant_meta.bin`, and per-segment `hnsw_seg_<start>.bin` / `ivf_seg_<start>.bin` / `quant_seg_<start>.bin`. `quant.bin` is still a **generation-wide** mutable code array (mapped per segment in memory) and `quant_seg_<start>.bin` is a derived per-segment copy of the same codes, so quantized collections store the codes twice until T9 lands. A segment's `id_tracker.staged` is a checkpoint-private file: it becomes `id_tracker.bin` only at publish time. There is no generation-wide `dense_snapshot.bin` / `vectors.bin` / `keys.bin` / `tombstones.bin`; the id directory is restored from the per-segment trackers and WAL replay. `kind` / `named` keep root type markers but all immutable space config lives in the checksummed `spaces.json` inside the generation; their vector/payload bytes live in `spaces/<space>/segments/<start>/` (`points.bin` / `payloads.bin`) via `SegmentedBlobs` (global logical offsets mapped to per-segment files), postings in `spaces/<space>/postings/`, and dense named spaces may have `spaces/<space>/ann/` HNSW graphs. Blob headers stamp a dtype tag in byte `[1]` (`0`=f32 keeps the old layout); WAL upserts store blob references, not inline vectors (`wal/blobs.bin`, append-only for the lifetime of the log: nothing reclaims it except a full `Wal::truncate()`, which production paths do not call, so blob bytes grow with every upsert and are reported as `MaintenanceStatus::wal_blob_bytes` rather than counted into the checkpoint trigger). Any commit file with a bad magic/CRC is `CorruptData` — no legacy-layout read path remains.
- **Generation commits.** `generation.bin` (checksummed `{version, generation, lsn}`) is the commit point. Checkpoints flush each dirty segment in parallel (rayon), each segment fsyncing its own vectors/keys/tombstones/tracker/payloads and advancing its persisted watermark independently; ACK is the minimum of all segment watermarks clamped by generation lsn and live WAL pins, then `wal/acked-lsn` is published. A single segment flush failure leaves the generation and ACK unadvanced, marks maintenance unhealthy, and does not poison writes. A `vector_dtype.bin` sidecar is written per segment and strict-verified on open. Each segment's `id_tracker` is written to `id_tracker.staged` during the unlocked flush and renamed into place only inside the queue gate after the re-flush, so a visible tracker always names bytes that are already durable; the tracker also records the segment frontier `lsn`, and open caps each point's water mark at it so replay can still re-apply anything newer than the tracker. Compaction writes a whole new generation under `.g*-staging/`, fsyncs it, renames it to `g<id>`, publishes the manifest, then switches in-memory handles and only then truncates the WAL. Once published, any failure before the in-memory switch poisons the store: reads continue but writes/checkpoint/compact are rejected until reopen. Open ignores staging dirs, rejects a WAL ack newer than the manifest (dense), a missing/mismatched `spaces.json` or `vector_dtype.bin`, and tracker CRC failures. Snapshot manifests bind generation files to the generation id and WAL segments to their first lsn; incremental snapshots hard-link identical entries.
- **The WAL is a directory.** `wal/<20-digit first-lsn>.bin` (segment format v2: 32-byte header with magic/version/random seed/first-lsn, 8-byte aligned records, chained CRC over length + payload + zero padding, zero length = preallocated slack); a txn never spans segments; segments are preallocated to `StorageConfig::wal_segment_bytes` (default 64 MiB) with a capacity-matched `.spare` prebuild consumed on rollover, served through mmaps with one `flush_range` per group-commit batch; replay and open-time prefix scans use read-only mmaps and scan records sequentially without a separate index. Each dense store tracks per-segment applied/persisted LSNs and holds a `WalAckPins` registry; checkpoints and compaction truncate through the watermark clamped by the lowest live pin (unlink fully covered segments); `truncate()` is the full-wipe helper retained for test teardown, not a production compaction path. Both paths first publish `wal/acked-lsn` (CRC32-protected `{generation, lsn}`) and fsync the WAL directory; stores bind the log to their generation at open and after compaction publish, so an ack from another generation reads as zero. Dense replay uses the generation manifest lsn as its floor and skips records whose lsn is not newer than the per-id version water mark; exact-scan stores replay from the generation manifest lsn with `read_all_from`, never from the WAL watermark. A torn tail record is tolerated in the **last** segment only — damage anywhere else is `CorruptData`, never silent truncation. Rollover truncates the closed file to its valid prefix, so a torn tail can never be sealed into a middle segment. Replay also requires each closed segment's last lsn to be exactly one below the next segment name; gaps and overlaps are `CorruptData`, never silent skips. Checkpoint/compaction markers always carry freshly allocated LSNs (never the watermark). The commit-queue worker is the only bulk LSN assigner (rollback on flush failure, so no holes); slots are assigned at apply time in log order; payload WAL records are keyed by external point id and resolved through the id tracker on both live and replay paths.
- **Filter planning and snapshots.** `PayloadIndexManager::plan_filter` narrows candidates with `must` / `must_not` / `should` / `min_should` bitmaps; Numeric/Map/Text/Geo plus per-field shape indexes cover equality, ranges, tokens, radius/box, `IsNull` / `IsEmpty` / `ValuesCount`, and any unindexed clause disables that group's narrowing while the full filter still runs on every candidate. `field_indexes.bin` is derived: a generation/lsn/definition mismatch is discarded and rebuilt from payload bytes and WAL replay. Sparse named/kind spaces persist per-term document frequencies in `postings/manifest.bin` and use them only to choose posting accumulation versus full scan. `CollectionStore::snapshot_to` registers a WAL acknowledge pin over the copy window and copies the serving generation plus the whole WAL under the maintenance lock, queue gate and store read lock, and writes a CRC-checked `snapshot.json`; each entry carries file version, length and CRC. `snapshot_to_incremental(base, dest)` verifies the base snapshot and hard-links entries whose version/length/CRC all match, copying only changes; the result is still a complete self-contained tree. `verify_snapshot` validates lengths/CRCs and rejects escaping manifest paths; `restore_snapshot(src, dest)` copies a verified snapshot into a new directory and opens it to validate. The engine exposes dense snapshot methods, and the C ABI exports all four (`simvec_snapshot_collection`, `simvec_snapshot_collection_incremental`, `simvec_verify_snapshot`, `simvec_restore_snapshot`) with the five native bindings wrapping them; wasm keeps its own OPFS JSON snapshot instead.
- **Single writer per collection.** All dense/kind/named `create`/`open` paths hold an advisory `flock` on the root `.lock` file for the store's lifetime. Handles in one process share the lock by `(dev, ino)` with a reference count, so promote/restore renames keep sharing it; another process opening the same directory fails immediately. The OS releases the lock on process exit.
- **Checkpoint order for `kind` / `named` is load-bearing:** `blobs.sync() → postings.flush(Some(lsn)) → checkpoint_payloads (append + sync) → snapshot::write → wal.truncate_through(lsn)`; every sync propagates I/O errors before the manifest advances. `postings/manifest.bin` must carry the same `lsn` as the snapshot; when they differ the dictionary is discarded and rebuilt from the snapshot, never patched incrementally. `points.bin` and `payloads.bin` are therefore **derived data** — `kind`/`named` WAL records still inline the full vector and JSON payload, so replay re-appends both kinds of blobs.
- **Scratch dirs** `*.rebuild-*`, `.old-*`, `.suspect-*` exist only for crash recovery and are never loaded into the serving registry — don't scan them in tests.
- Background compaction is scheduled from per-segment garbage ratios; the appendable tail is excluded whenever a frozen segment sits in front of it, while a collection that has only the tail stays eligible (otherwise a small collection could never reclaim garbage). Compaction still rewrites the **whole generation** and re-packs every live slot into a dense prefix (`meta.next_slot = live_count`), so segment `start`/capacity and every later slot range move, and all segment ANN/quant files are rebuilt. Incremental per-segment compaction plus a tracker-driven free-slot list is the open item tracked in `docs/plan/deferred-storage-completion.md` (T9); slot allocation is still monotonic through `meta.next_slot`, and the tracker's `free` flag never feeds an allocator.
- HNSW and IVF are each built as one derived file per complete dense segment; segment-local ids map to global vectors through `slot_base`, and quantized codes are written to matching `quant_seg_<start>.bin` files. A corrupt or missing segment file only removes ANN acceleration for that segment, whose slots join the exact-scan pending set. Deleting a dense point locally heals the affected in-memory HNSW neighborhoods (the persisted graph is unchanged and tombstones still filter results); compaction remains the full topology repair. The partial tail stays in `pending` and is exact-scanned until a segment completes; drain and repair rebuild only the affected segment. HNSW promotion is automatic past `full_scan_threshold` (default 10 000); a background maintenance worker runs every 30 s. ANN tiers: the default dense space gets per-segment HNSW/IVF/quant files; a named dense space gets one HNSW graph at `spaces/<space>/ann/hnsw.bin` (built over global slots, `slot_base = 0`, published at checkpoint) and **no** IVF or quantization — selecting IVF there silently means exact scan, and multi uses MaxSim only. Sparse spaces use postings plus exact scan, never ANN.
